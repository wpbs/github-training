# Create a Docker action

Create the action in a new folder `hello-world-docker-action` in [your lab repository](../).

1. Create the folder `hello-world-docker-action` in your repository by creating its first file, [`hello-world-docker-action/action.yml`](/../../new/main?filename=hello-world-docker-action%2Faction.yml). If you want a more complete starter with tests, linting and a release workflow, look at [actions/container-action](https://github.com/actions/container-action) for inspiration, but keep the files in this folder of your lab repository.

2. The folder needs three files: [`action.yml`](/../../new/main?filename=hello-world-docker-action%2Faction.yml), [`Dockerfile`](/../../new/main?filename=hello-world-docker-action%2FDockerfile) and [`entrypoint.sh`](/../../new/main?filename=hello-world-docker-action%2Fentrypoint.sh). Create them (and look at the [actions/hello-world-docker-action](https://github.com/actions/hello-world-docker-action) example to see what each does).

<details>
  <summary>Solution: action.yml</summary>

```YAML
name: Hello World
description: Greet someone and record the time
inputs:
  who-to-greet:
    description: Who to greet
    required: true
    default: World
outputs:
  time:
    description: The time we greeted you
runs:
  using: docker
  image: Dockerfile
  env:
    INPUT_WHO_TO_GREET: ${{ inputs.who-to-greet }}
```

</details>

<details>
  <summary>Solution: Dockerfile</summary>

```Dockerfile
FROM alpine:3.23
WORKDIR /usr/src
COPY entrypoint.sh .
RUN chmod +x /usr/src/entrypoint.sh
ENTRYPOINT ["/usr/src/entrypoint.sh"]
```

</details>

<details>
  <summary>Solution: entrypoint.sh</summary>

```bash
#!/bin/sh -l

GREETING="Hello, $INPUT_WHO_TO_GREET!"

# Workflow command: show an annotation in the run summary
echo "::notice file=entrypoint.sh::$GREETING"

# Write outputs to the $GITHUB_OUTPUT file (not ::set-output)
echo "time=$(date)" >>"$GITHUB_OUTPUT"
```

</details>

3. The `Dockerfile` already makes `entrypoint.sh` executable inside the image, so no extra step is needed for the executable bit.

> **Note**
> Docker actions only run on Linux runners, and not on `ubuntu-slim` (it has no Docker).

Commit your files (`[skip ci]` to not run a build, yet) and continue with [Testing the action](04-My-first-action.md#testing-the-action).

## Optional: use an image from a private registry

A Docker action that points to a registry image (`image: docker://ghcr.io/<owner>/<image>:<tag>`) or a `uses: docker://` step only supports **public** images: the image is pulled while the job is initialised, before any step (like a login) can run. To use a private image, wrap `docker login`, `docker run` and `docker logout` in a composite action and pass the credentials in as inputs.

1. Build the image from your `hello-world-docker-action` folder and push it to a private repository on a registry you can access, for example `ghcr.io/<owner>/hello-world-docker-action:1`. Note the registry, image name, and a username and password (or token) that can pull it, and store the password as a [repository secret](/../../settings/secrets/actions) `REGISTRY_PASSWORD`.

2. Create the composite action [`hello-world-docker-private-action/action.yml`](/../../new/main?filename=hello-world-docker-private-action%2Faction.yml) which takes the registry, image, username and password as inputs, and runs the image with the `who-to-greet` input.

<details>
  <summary>Solution: action.yml</summary>

```YAML
name: Hello World (private image)
description: Greet someone using an image from a private registry
inputs:
  who-to-greet:
    description: Who to greet
    required: true
    default: World
  registry:
    description: Registry host, for example ghcr.io
    required: true
  image:
    description: Full image name including tag
    required: true
  username:
    description: Registry username
    required: true
  password:
    description: Registry password or token
    required: true
outputs:
  time:
    description: The time we greeted you
    value: ${{ steps.run.outputs.time }}
runs:
  using: composite
  steps:
    - name: Docker login
      shell: bash
      env:
        REGISTRY: ${{ inputs.registry }}
        USERNAME: ${{ inputs.username }}
        PASSWORD: ${{ inputs.password }}
      run: echo "$PASSWORD" | docker login "$REGISTRY" --username "$USERNAME" --password-stdin

    - name: Docker run
      id: run
      shell: bash
      env:
        IMAGE: ${{ inputs.image }}
        INPUT_WHO_TO_GREET: ${{ inputs.who-to-greet }}
      run: |
        docker run --rm \
          --env INPUT_WHO_TO_GREET \
          --env GITHUB_OUTPUT=/github/output \
          --volume "$GITHUB_OUTPUT:/github/output" \
          "$IMAGE"

    - name: Docker logout
      if: always()
      shell: bash
      env:
        REGISTRY: ${{ inputs.registry }}
      run: docker logout "$REGISTRY"
```

</details>

3. Call the action from a workflow, passing in the credentials. Reference the action with `$/hello-world-docker-private-action` and run it on a Linux runner with Docker.

<details>
  <summary>Solution</summary>

```YAML
      - uses: actions/checkout@v6
        with:
          persist-credentials: false

      - uses: $/hello-world-docker-private-action
        with:
          who-to-greet: Mona
          registry: ghcr.io
          image: ghcr.io/<owner>/hello-world-docker-action:1
          username: <username>
          password: ${{ secrets.REGISTRY_PASSWORD }}
```

</details>

> **Note**
> - The `docker logout` step uses `if: always()` so the credentials don't stay on the runner when the run step fails. On GitHub-hosted runners the machine is discarded after the job, but self-hosted runners may be reused.
> - The container isn't a Docker action anymore, so it doesn't get the `GITHUB_*` environment variables or mounts automatically. The example mounts the `GITHUB_OUTPUT` file to let the entrypoint write its `time` output. Pass other variables or files the same way if your image needs them.
> - A job-level `container:` with `credentials:` is the alternative if you want all steps of a job to run in the private image. See [Containers in GitHub Actions](03-Containers.md).
